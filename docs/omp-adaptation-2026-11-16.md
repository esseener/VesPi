# OMP 适配与能力判断（1.1.17）

当前产品主链路为 OMP 18.20.3 TUI → node-pty → Electron IPC → xterm。旧 RPC 代码仍服务于部分历史会话功能，不能用它的进程或状态冒充用户眼前的 TUI。

## 已落实的适配

| 项目 | 发现的问题 | 修复与验证方式 |
|---|---|---|
| 思考等级 | 旧字段 thinking.defaultLevel 无效；恢复会话会覆盖默认档位 | 使用 defaultThinkingLevel；明确修改时传原生 --thinking，其他设置保留当前档位；真实会话切换验证 |
| 外观设置 | 修改思考时重置主题；GUI/YAML 并行写且吞错 | 单条设置保存路径、局部 YAML 更新、错误显示；真实验证主题/符号集不变 |
| 模型目录 | JSON 回退丢失能力；隐藏 OAuth/YAML-only 模型 | 读取 omp models --json，保留上下文、输出上限、图像和思考能力 |
| 模型编辑 | 读旧 JSON；嵌套对象序列化成字符串 | YAML 优先读；保留对象、数组、未知顶层字段；解析往返测试 |
| 当前会话 | 设置重启使用另一 RPC 会话或不确定的 --continue | TUI 扩展报告 PID、会话文件、模型、思考、忙闲和完成次数；按 PID 校验；恢复确切会话 |
| 运行状态 | 弹窗显示旧 RPC，启动按钮可能额外开一个内核 | 弹窗读取真实 TUI；模型标签定期同步；去掉误导的 RPC 状态控制 |
| 会话选择 | 浏览历史会话时另起 RPC，可能双进程写同一会话 | TUI 运行时只验证会话文件，由原生 /resume 导航；跳过 RPC 历史加载 |
| 权限 | 原 TUI 未接入壳权限 | 加载权限扩展和规则/信任环境；真实 write/read 与确认框验证 |
| 环境说明 | 描述旧聊天卡片和不存在的面板 | 独立 vespi-tui-context.md，只说明真实桌面环境和原生工具关系 |
| 提示音/滚动 | 原来依赖旧聊天事件 | 使用真实 TUI 完成计数；关闭自动滚动时保留 xterm 视口 |
| 启动 | 忽略自定义 OMP 路径、缺失时回退 shell | 使用选定的 OMP 路径；缺失明确报错；恢复上次会话选项传到 TUI |

## 怎样提高实际能力

1. **模型能力完整性优先。** 保留真实上下文窗口、输出上限、图像与思考档位，防止壳层把模型降级为仅有名称的配置。用同一测试任务比较成功率、返工次数、耗时和成本，不能凭更高档位推断质量必然提高。
2. **规划与执行使用 OMP 原生机制。** plan.enabled 已开启；复杂需求先明确验收点和依赖，执行后运行实际检查。旧 GUI 会审配置不作用于 TUI，已移除对应设置及检测逻辑。旧 RPC 会审后端尚存，不宣称整个后端已删除。
3. **并行只用于独立任务。** OMP 原生 task/subagent 已有相应设施；适合并行检索、独立模块审查，有共享写入的任务须隔离。当前不自动启用收费 advisor 或切换更便宜的 prewalk 模型，先用真实任务评估收益。
4. **代码智能优先于盲目文本替换。** lsp.enabled 已开启；语言服务器实际可用性取决于项目语言与安装环境。自动诊断和格式化属于内核已有能力，不能算作本次新增。
5. **长任务上下文要可恢复。** 自动/中途/异步 compaction 已开启；使用原生任务状态与 context_notes 维护目标、验证结果和剩余工作。memory.backend 当前为 off；启用持久记忆需先选定本地/远端后端及保存范围，避免混入过期结论和凭据。
6. **工具闭环验证。** 文件任务验证磁盘内容；浏览器任务验证目标页面与实际操作结果；模型回复“完成”本身不足以证明成功。
